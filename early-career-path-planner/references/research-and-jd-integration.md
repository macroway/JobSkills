# 岗位检索与 JD 融合

## 当前市场样本

对每个候选岗位先固定工作城市：用户填写的工作城市，或北京。至少记录 5 条近 90 天、发布日期可核验的职位，覆盖 2 个或以上发布方。优先顺序：企业官网招聘页、企业校园招聘页、可信招聘平台的完整职位页、政府/行业组织的职业说明。

每条来源至少记录以下字段：

| 字段 | 说明 |
| --- | --- |
| 编号 | 例如 `POST-PM-01`、`AUTH-01`、`LOCAL-JD-01`。 |
| 标题与岗位名 | 保留页面原名，另记录归一化后的候选岗位名。 |
| 发布方与城市 | 职位公司/平台和样本城市。 |
| 发布日期 | 仅记录页面明确显示的日期。 |
| 访问日期 | 实际访问的日期，不替代发布日期。 |
| URL 或本地路径 | 外部来源为 URL；努力方向 JD 为相对或绝对本地路径。 |
| 可用内容 | 岗位职责、必备条件、加分项或职业定义。 |

没有明确发布日期的页面记为 `发布日期缺失`，只可补充岗位内容。职位过期、转载重复、只有标题没有职责要求的页面不计入 5 条样本。样本不足时如实报告数量、平台覆盖和限制。

## 本地努力方向 JD

本地目录为：`skills/early-career-path-planner/references/jobmap/`。

查找与选择顺序：

1. 精确岗位名：列出所有文件名以 `<候选岗位>-` 开头的 JD，不以文件名末尾的“校招/初级/中级”等标签筛选。
2. 逐份读取“岗位信息”表中的“工作年限”，将其与用户的努力方向 JD 工作年限比较。优先选择工作年限相符的文件；并从工作年限归一化出职责尺度，而不是相信文件名职级后缀。
3. 如果精确岗位名文件存在但没有年限相符项，选择工作年限最接近的文件，并在来源与岗位卡中写明“年限不完全匹配”。
4. 只有不存在任何精确岗位名文件时，才查找同一职能的常见同义岗位名，例如“数据分析师/商业分析师”“软件工程师/后端开发工程师”。
5. 如不存在可用文件，记录“本地努力方向 JD 缺失”，仅使用已核验的公开岗位样本。

读取本地 JD 时记录它的“职级/类型”“工作年限”“岗位职责”“必备条件”“加分项”。本地 JD 表达努力方向的能力深度，不代表本次城市的实时岗位数量或招聘事实。

## JD 工作年限归一化与选择

只读取 JD 正文“岗位信息”中的“工作年限”，不从文件名、岗位名称或职责难度反推年限。先将常见写法归一化：

| 正文写法 | 归一化结果 |
| --- | --- |
| 校招、应届、0–1 年 | 0–1 年 |
| 1–3 年、3–5 年、5–8 年、8 年以上 | 保留对应区间 |
| 1 年以上、3 年以上、5 年以上 | 1+ 年、3+ 年、5+ 年 |
| 经验不限、面议、缺失 | 年限未明确，不能作为“相符”的依据 |

对精确岗位名的候选文件按以下顺序选择：

1. 与目标工作年限区间完全相同；
2. JD 区间覆盖目标区间，或“X 年以上”的下限与目标区间下限相同；
3. 与目标区间有重叠；
4. 只有前述情况都不存在时，选择下限最接近的已明确年限，并标记“年限不完全匹配”。

“年限未明确”的文件可作为职责补充，但不得被写成已匹配的努力方向 JD。输出匹配结果时使用“完全匹配、覆盖匹配、重叠匹配、年限不完全匹配、年限未明确”之一，并同时保留原文工作年限。

## 融合方式

岗位卡需分别呈现：

| 区块 | 依据 | 写法 |
| --- | --- | --- |
| 当前市场 JD | 近期公开职位样本 | 仅概括多条样本重合的职责和要求。 |
| 努力方向 JD | 本地同职能、工作年限与目标区间相符的 JD | 概括下一层级要承担的范围、决策和交付物，并保留其原始职级/类型。 |
| JD 融合结论 | 两类材料与用户证据 | 写共同要求、差异、最优先补齐的能力，以及可证明完成的成果。 |

对于相互矛盾的要求，不强行合并。说明它们分别来自哪类材料，并优先规划在多数近期样本中出现、且能被作品或经历验证的能力。
