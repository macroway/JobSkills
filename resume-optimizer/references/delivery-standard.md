# 中文简历交付标准

## 模板权威

- 模板文件：`../assets/中文简历模版.docx`
- 原始来源：用户提供的《中文简历模版.docx》
- SHA-256：`252897222cfedf3973abd090f057779b22483d3dfa616410ad41f87efdbe2fbf`
- 使用方式：复制模板后在现有槽位内替换内容。不要从空白文档仿制，不要修改或覆盖模板原件。

每次生成简历前校验模板哈希。哈希不一致时停止使用，重新确认模板来源并重新提取版式。

## 版式基线

| 项目 | 模板标准 |
| --- | --- |
| 页数 | 严格 1 页 |
| 页面 | Letter，纵向，8.5 × 11 英寸 |
| 页边距 | 左右各约 0.72 英寸，上约 0.28 英寸，下约 0.19 英寸 |
| 中文字体 | 方正楷体_GB2312，设置 `w:eastAsia`；使用模板内嵌字体 |
| 姓名 | 16 磅、加粗、居中 |
| 联系方式 | 9 磅、加粗，使用模板制表位横向分布 |
| 一级栏目 | 约 10.5 磅、加粗，沿用模板下边框横线 |
| 经历抬头 | 约 10 磅、加粗；单位或项目在左，角色在中，日期在右 |
| 正文与项目符号 | 9 磅；沿用模板悬挂缩进和紧凑行距 |
| 提示色 | 黄色文本高亮，仅用于待用户补充的内容 |

这些数值用于审计和克隆新增槽位。编辑既有槽位时优先保留其原始段落、运行、制表位、边框、缩进和间距属性，不要按近似数值重建。

## 栏目与顺序

沿用模板的页面结构：

1. 姓名、电话、邮箱、地点及可选照片；
2. 自我评价；
3. 教育背景；
4. 实习经历或工作经历；
5. 课外经历；
6. 项目经历；
7. 个人特质，包括语言、工具或技能及必要的兴趣信息。

只保留用户确有内容且有助于目标岗位的栏目。删除空栏目时保持其余栏目的相对顺序与视觉样式，不用虚构内容填充。

## 经历条目标准

每条经历使用：

```text
【★能力短标题】STAR 融入正文的经历描述 + 量化成果
```

- `【★能力短标题】` 必须位于条目开头并加粗，通常为 4–10 个字。
- 短标题写能力或交付价值，如 `【★模型评估优化】`，不写空泛品质，如 `【★认真负责】`。
- 正文自然覆盖情境或目标、个人承担的任务、关键行动和结果，不显示 STAR 字母标签。
- 先写最能证明目标岗位能力的动作和结果，少写团队背景和过程铺垫。
- 每条尽量控制在一至两行；同一经历通常保留 2–4 条。

合格示例：

```text
【★数据分析提效】针对月度报表人工汇总易出错的问题，使用 Python 清洗并校验 12 万条记录，将出表周期从 2 天缩短至 4 小时，差错率降至 0.5%。
```

## 量化与黄色待补提示

优先检查以下数据：业务或数据规模、完成周期、效率变化、准确率或质量、收入或成本、覆盖人数、交付数量、排名及同比或环比变化。

缺少必要数据时，在结果所在位置写具体提示，并设置 Word 黄色文本高亮：

```text
【★活动统筹推进】统筹校级招聘会的场地、嘉宾和志愿者安排，协调 【请补充：志愿者人数】 名成员完成现场执行，服务 【请补充：参会企业及学生人数】。
```

不要：

- 猜测或补造数字；
- 高亮整条经历；
- 只写“待补数据”；
- 用黄色字体代替黄色文本高亮；
- 把待补问题移到文末，导致用户无法判断对应位置。

## 一页取舍顺序

页面超出时，按下列顺序压缩：

1. 删除无关经历、重复动作和空泛自我评价；
2. 保留与目标岗位最匹配且证据最强的条目；
3. 合并相似动作，删去无法体现个人贡献的铺垫；
4. 压缩课程、兴趣、弱相关奖项和次要经历；
5. 微调模板已有间距。

不得缩小模板页边距，不得把正文压到 9 磅以下，不得删除成果数据来换取篇幅，也不得通过文本框叠放或隐藏文字规避一页检查。

## 最终验收

- 通过文本检查确认没有 `XX`、`XXXXX`、模板指导语或未处理的示例内容。
- 通过 DOCX 结构检查确认中文运行和样式的东亚字体为 `方正楷体_GB2312`。
- 通过渲染确认只有一页，且照片区、标题横线、制表位、项目符号和日期对齐与模板一致。
- 逐项检查黄色高亮；每处都应是明确、真实需要用户补充的数据。
- 检查文字是否截断、重叠、贴边、意外换行或溢出。
- 交付前再次校验模板原件 SHA-256，保证模板本身未被改动。
